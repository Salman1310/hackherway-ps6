THE PROBLEM
-----------
At Sun Life, getting system access as a new joiner or role-changer is broken.
A single onboarding can require 4-8 separate tickets across ServiceNow, Jira,
email, SAM, and cloud tools. Approvers are unclear. No central tracking exists.
End result: access provisioning takes anywhere from 2 to 30 days.

Joiners have zero visibility. Managers are the bottleneck. And nobody can audit
who approved what, when, and why.


THE IDEA
--------
One AI-driven web app replaces the entire fragmented process.

The joinee opens a chat interface, enters their ACF2 ID, and has a conversation
with an AI agent. The agent verifies their identity against Workday, understands
their role (asking clarifying questions if the input is vague), matches them to
a persona-based access template, lets them confirm mandatory and optional access
items, and then routes everything as a single bundled approval request through
MS Teams.

Approvers get a card in Teams. One click to approve or reject. The system
provisions all tools in parallel on approval. The joinee sees live status in the
same chat interface they started in.

No tickets. No email chains. No mystery.


WHAT MAKES IT INTELLIGENT
--------------------------
Three AI capabilities sit on top of the core flow:

Agent A - Ambiguity Resolution
  The joinee says "I do backend stuff." The agent asks the right questions until
  role, seniority, and employment type are all resolved. Only then does it
  retrieve an access template. This replaces the static dropdown forms that
  break the moment someone's title doesn't match a predefined list.

Agent B - Privilege Accumulation Detection (D3)
  Before the request is submitted, the system checks if the new access bundle
  combined with the joinee's existing permissions creates a dangerous
  combination (e.g. production DB write + deploy pipeline write). If it does,
  the agent surfaces a plain-language warning in the chat and flags it. Critical
  combinations are auto-escalated to the security team regardless of what the
  joinee clicks.

Agent C - Live Status Queries
  After submission, the joinee can ask "what's the status of my request?" at any
  time. The agent queries the live approval state and responds conversationally.
  No refresh. No ticket portal. No calling IT.

Additional intelligence (D2):
  Each Teams approval card includes an anomaly risk score (0-100) with a
  plain-language explanation. Approvers see not just what is being requested,
  but whether it looks unusual and why.


TECHNOLOGY DECISIONS (LOCKED)
------------------------------
Frontend       Next.js (App Router) + Tailwind CSS
               Running in web/ subdirectory

LLM            Gemini 2.0 Flash (primary) - free tier, 1M tokens/day
               Groq Llama 3.3 70B (fallback)

Database       Supabase (PostgreSQL + pgvector)
               Zero Supabase-specific features - plain SQL throughout
               Drop-in compatible with AWS RDS PostgreSQL for production

Embeddings     nomic-embed-text via Ollama (local, 768 dimensions)
               Used for RAG-based persona template matching

Approval       MS Teams Incoming Webhook + Adaptive Cards
               Approve/Reject buttons call back to /api/approve and /api/reject

Auth           BYPASS_AUTH=true for the hackathon
               Azure AD + MSAL proposed for production (Sun Life already uses it)

External       All external systems (Workday, ServiceNow, Jira, AD/LDAP, SAM)
Systems        are mocked locally. Pre-seeded with 4 demo ACF2 IDs.

Public URL     ngrok required for Teams approve/reject callbacks
               (Teams cannot call localhost)

PHASE 1 - WHAT WAS BUILT
--------------------------
Location: Hackathon/web/

Three-panel layout matching the Sun Life Ask design language:
  Left sidebar   Dark background with diagonal texture, gold "New Request"
                 button, request history placeholder with 3 items
  Center chat    White panel, bot avatar (gold sun icon), message bubbles
                 (bot = gray left, user = gold right), auto-scrolling,
                 bottom-anchored textarea input with dark circular send button
  Right panel    Top: "Access Template" skeleton with 3 placeholder cards
                 Bottom: "Request Status" 4-step timeline tracker

Hardcoded welcome message on load:
  "Hi! I'm here to help set up your system access.
   Let's get started. What's your ACF2 ID?"

Session state wired (empty, ready for Phase 2):
  acf2_id, workday_context, resolved_role, selected_template,
  final_bundle, request_id

Mobile: sidebar hidden behind hamburger toggle on small screens.
Right panel: hidden below xl breakpoint.

Colors: gold #FFD100, dark background #1E1E2E
Stack:  Next.js 16.2.4, Tailwind CSS v4, TypeScript, lucide-react
